01 / SERVICE OVERVIEW

음성·채팅에 AI 캐릭터가 반응하는 방송 앱

게임을 진행하며 채팅을 확인하고 반응까지 이어가야 하는 1인 스트리머를 위한 데스크톱 콘솔입니다. 스트리머의 음성과 시청자 채팅을 바탕으로 AI 캐릭터가 반응하고, OBS 오버레이를 통해 방송 화면에 함께 등장합니다.

대상 사용자

1인 방송인과 방송 입문자, 캐릭터를 활용하는 버추얼 방송인.

서비스의 역할

대화 보조와 채팅 분석, 캐릭터 설정과 송출 관리를 하나의 흐름으로 연결.

AI 페르소나 설정실시간 대화·채팅 분석2D·3D 캐릭터OBS 오버레이방송 통계·안전 관리
서비스 소개와 캐릭터 미리보기 ↗

PROBLEM & USER RESEARCH

빈 시간을 채우되, 방송의 주도권은 스트리머에게

혼자 방송을 진행하면 콘텐츠 진행과 채팅 확인, 대화의 흐름을 동시에 챙겨야 합니다. Live Buddy는 스트리머를 대신하는 진행자가 아니라, 필요할 때 불러 함께 이야기하고 방송에 반응을 더하는 AI 동료를 목표로 했습니다.

스트리머와 AI의 티키타카

26명이 스트리머와 주고받는 AI 대화를 선택했습니다.

설문에서 확인한 한계와 설계 방향 ＋

지속적으로 쓰면 좋겠다는 응답은 13.2%, 한 번쯤 보면 재미있겠다는 응답은 60.3%, 필요 없거나 재미없을 것 같다는 응답은 17.6%였습니다. 일회성 관심과 장기 사용 의향은 달랐으며, 이 설문을 시장 전체의 수요나 제품 효과로 일반화하지 않았습니다.

방송 집중을 방해할 수 있다는 의견도 있었습니다. 사용자가 PTT·이름 호출로 참여 시점을 정하고, AI 참여를 제어하며 새 발화로 응답을 중단할 수 있도록 구성했습니다. 장기 사용성과 실제 방송 부담 감소는 추가 검증 과제입니다.

LIVE DEMO / 실제 구현 영상

이름을 부르면 대답하는, 나의 AI 방송 동료

혼자 방송해도 함께 이야기할 동료가 있도록 만들었습니다. 데스크톱 앱에서 PTT(Push-to-Talk)로 말하거나, 음성 인식(STT)으로 설정한 AI의 이름을 부르면 AI가 호출을 인식하고 음성과 캐릭터 반응으로 대화를 이어갑니다.

재생 후 소리를 켜면 스트리머의 발화와 AI의 음성 응답을 함께 확인할 수 있습니다.

  1. 01

    PTT 또는 이름으로 호출

    PTT로 음성을 입력하거나, 설정한 AI 이름을 불러 대화를 시작합니다.

  2. 02

    AI가 알아듣고 대화

    인식된 발화에 AI가 응답하고, 음성과 캐릭터의 반응이 이어집니다.

  3. 03

    OBS로 방송 화면에 함께 등장

    AI 캐릭터를 OBS 오버레이로 송출해 시청자도 방송 동료와의 대화를 함께 볼 수 있습니다.

APP DEVELOPMENT / 이정현

Electron·React 기반 데스크톱 UI, 방송 대시보드, 캐릭터 설정, 통계·채팅 분석 화면을 구현했습니다. 전역 상주 서비스와 로컬 음성 인식, 음성 재생·립싱크, OBS 오버레이 연동 및 macOS·Windows 앱 패키징을 담당했습니다.

팀 협업 Spring Boot API, Gemini Live 연동, FastAPI 채팅 수집, Redis와 AWS 서버 인프라는 백엔드·AI 담당 팀원의 영역입니다. 해당 API·이벤트를 받아 사용자가 조작할 수 있는 화면과 동작으로 연결했습니다.

DESIGN DECISIONS / MY WORK

장시간 켜 두는 방송 앱에 맞춘 기술 선택

ELECTRON

웹 화면을 데스크톱 기능과 연결

React 화면을 유지하면서 투명 오버레이 창과 독립적인 백그라운드 실행을 연결하기 위해 선택했습니다. 마이크·단축키·로컬 STT와 OBS 연동까지 앱의 실행 환경에서 다뤘습니다.

ZUSTAND

여러 화면이 같은 방송 상태를 공유

로그인·방송·캐릭터 상태를 여러 컴포넌트에서 사용하기 위해 도입했습니다. 간결한 상태 관리와 TypeScript 연동을 선택 이유로 정리했고, 방송 처리는 전역 서비스에 두어 화면 전환과 분리했습니다.

REACT HOOK FORM · ZOD

입력 상태와 검증 규칙을 분리

React Hook Form으로 입력·제출을 관리하고 Zod 스키마로 검증 규칙을 정의했습니다. 검증 결과를 화면에 반영하고 폼의 불필요한 리렌더링을 줄이는 방향으로 구성했습니다.

AXIOS · REQUEST QUEUE

토큰 만료 때 요청을 한꺼번에 복구

여러 요청이 동시에 401을 받아도 첫 요청만 토큰을 갱신하고 나머지는 큐에서 기다리게 했습니다. 성공하면 새 토큰으로 재시도하고, 갱신 실패 시 인증을 정리해 로그인으로 이동합니다.

WS·STT·TTS 핵심 로직을 React 컴포넌트 밖의 싱글턴 서비스로 분리했습니다. 컴포넌트는 useStreamWS, useSTT 같은 얇은 훅으로 상태를 읽고, Zustand로 UI와 방송 상태를 동기화합니다. setBroadcast·clearBroadcast로 세션 상태를 한 번에 설정·정리합니다.

02로컬 음성 인식과 Push-to-Talk＋

MediaRecorder가 녹음한 음성을 Electron IPC로 전달하고, 로컬 Faster Whisper에서 텍스트로 변환한 뒤 방송 WebSocket으로 전송합니다. Python 데몬을 상주시켜 모델을 매번 불러오지 않도록 했습니다. 전역 PTT와 앱 내부 PTT를 지원하며, 사용자가 발화를 시작하면 AI 응답을 중단하는 Barge-in 흐름을 연결했습니다.

오디오 Blob은 큐에 보관하고 JSON은 이벤트 유형별로 분기해 VOICE_CHUNK 단위로 짝지어 처리합니다. 중단된 대화 턴의 후속 청크는 버려 이전 응답이 다시 재생되지 않게 합니다. 토큰·방송 ID 변화를 구독하고, 종료 원인에 따라 재연결 여부를 구분합니다.

Web Audio의 시간축에서 ttsNextStartTime을 기준으로 음성 청크의 시작 시점을 예약해 청크 사이의 공백을 줄였습니다. 컨테이너 디코딩이 실패하면 16bit PCM으로 직접 변환합니다. AnalyserNode로 오디오를 분석해 mouthOpen·viseme 값을 만들고 VRM·2D 캐릭터의 입 모양에 반영합니다.

스트리머의 새 발화가 시작되면 서버 응답을 기다리지 않고 로컬 음성과 대기 큐를 먼저 비웁니다. 중단된 응답의 턴 번호를 추적해 후속 청크를 버리고, 중단 완료 전 들어온 새 발화는 보관했다가 VOICE_INTERRUPTED 이후 전송하도록 연결했습니다.

Electron 앱과 STT 프로그램을 묶어 배포했습니다.

  1. 01

    버전 태그로 빌드 실행

    v* 태그를 GitHub에 올리면 GitHub Actions가 macOS·Windows 환경에서 빌드를 실행합니다.

  2. 02

    앱과 음성 인식 프로그램 패키징

    React·TypeScript 앱을 빌드하고, 로컬 STT 데몬은 PyInstaller 사이드카로 번들합니다. Electron 앱에 모델과 실행 파일을 포함해 별도 Python 환경을 준비하는 부담을 줄였습니다.

  3. 03

    DMG·EXE와 다운로드 페이지 제공

    macOS용 DMG와 Windows용 EXE를 GitHub Releases로 배포합니다. 소개 사이트는 landing/ 변경 시 GitHub Pages로 자동 배포되고, 설치 파일로 연결됩니다.

데스크톱 빌드 자동화 ↗소개 사이트 배포 ↗
서비스 전체 배포 환경 · 팀 협업

백엔드·AI 서버는 Docker 이미지로 빌드해 AWS EC2에 배포하고, Nginx가 HTTPS와 요청 중계를 담당합니다. Spring Boot·FastAPI·Redis, MySQL·S3·CloudFront가 연계된 환경이며, 서버 인프라 구축은 백엔드·AI 담당 팀원의 기여입니다.

05 / CHALLENGES & SOLUTIONS

음성·연결·입력 오류의 원인과 수정 내용

백엔드 로그를 활용한 AI 응답·음성·립싱크 연동

문제
지연을 최소화하면서 AI 응답 내용에 맞는 음성과 캐릭터 입 모양을 함께 출력하는 것이 과제였습니다. 백엔드의 모델 실행 결과를 실제 앱의 반응으로 연결하는 프론트엔드 처리를 담당했습니다.
분석
백엔드 담당자가 공유한 로그를 바탕으로 응답·음성 청크의 흐름을 확인하고, 프론트에서 답변 표시와 입 모양 처리가 어떻게 이어지는지 함께 살폈습니다.
해결
프론트에서 응답과 음성 청크를 대응시켜 처리하고, 음성 재생과 캐릭터 입 모양을 연결했습니다.

페이지를 바꾸면 종료되던 방송 연결

문제
화면 컴포넌트가 해제되면서 WS·STT 연결까지 함께 정리됐습니다.
해결
핵심 로직을 전역 상주 서비스로 옮기고, 훅은 상태를 읽는 역할로 줄여 화면과 방송의 생명주기를 분리했습니다.

macOS에서 반응하지 않던 음성 단축키

문제
미서명 배포본의 권한 무효화로 전역 단축키가 입력을 받지 못하는 상황이 있었습니다.
해결
앱에 포커스가 있을 때 DOM 키 이벤트로 동작하는 PTT 대체 경로를 마련했습니다. 타이핑 중 오작동과 포커스 이탈도 처리했습니다.

동시에 만료된 API 요청의 중복 토큰 갱신

문제
장시간 방송 중 여러 API가 동시에 401을 받으면 요청마다 토큰 갱신을 시도할 수 있었습니다.
해결
갱신 중 상태와 대기 큐를 두어 재발급을 하나로 모으고, 새 토큰을 받은 뒤 대기 요청을 재시도했습니다. 갱신 요청은 별도 클라이언트로 분리했습니다.

백엔드 로그와 프론트 처리 흐름을 함께 살피며, 모델 출력부터 사용자에게 보이는 응답까지 이어지는 연동 문제를 분석했습니다. 화면 전환과 연결 유지, 운영체제 권한 문제도 각각 분리해 처리했습니다.
